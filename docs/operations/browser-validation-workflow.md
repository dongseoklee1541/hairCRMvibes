# 브라우저 검증 작업 방식

이 저장소는 화면 탐색과 문제 재현으로 검증할 동작을 찾고, 반복 가치가 있는 절차를 스크립트로 남깁니다. 승인 범위와 필수 검증은 [AGENTS.md](../../AGENTS.md)의 §2, §4, §6, §8을 따릅니다.

## 도구 선택

| 목적 | 우선 경로 | 선택 기준 |
| --- | --- | --- |
| 새 화면 탐색, 사용자 흐름 파악, 문제 재현 | 사용 가능한 Ego Lite | 탐색이 필요한 경우에 사용합니다. 이미 재현 스크립트가 있으면 그것부터 실행합니다. |
| 반복 회귀 검증, 저장 결과 확인 | 기존 테스트와 Chrome/Playwright 스크립트 | 입력·기대 결과·실패 조건을 명시해 반복 실행합니다. |
| 사용자와 화면 검토 | Codex 내장 브라우저 | 현재 세션에 제공된 도구로 화면 확인과 피드백을 진행합니다. |
| 특정 브라우저·실기기에서만 발생하는 문제 | 해당 브라우저·기기 | 다른 환경의 성공 결과로 대체하지 않습니다. |

사용자가 지정한 도구가 우선입니다. 세션에 제공된 도구와 권한을 먼저 확인하고, 사용할 수 없는 경로는 이유를 기록한 뒤 목적을 충족하는 대체 경로를 선택합니다. 이 문서는 Ego 설치나 특정 브라우저의 상시 사용을 요구하지 않습니다. Codex의 브라우저 패널과 외부 도구의 선택은 구분하며, 문서를 바꾼 것만으로 앱의 브라우저 UI가 교체되거나 외부 브라우저가 연결된 것으로 간주하지 않습니다.

## 작업 순서

1. **범위 확인:** 브랜치·커밋·대상 URL·로컬/Preview/Production 환경·역할과 승인된 데이터 변경 범위를 확인합니다. 작업별 탭/Space, 서버 포트와 산출물 위치를 구분합니다.
2. **기존 검증 재사용:** 현재 문제를 다루는 테스트와 스크립트를 찾습니다. 동일한 커밋·환경의 유효한 결과가 있으면 근거를 기록해 재사용하고, 변경된 동작과 미해결 위험을 추가 검증합니다.
3. **최소 재현:** 합성·비식별 데이터로 필요한 화면과 조작만 재현합니다. 기대 결과와 실제 결과, 입력·포커스·스크롤·저장·재조회 시점을 구분합니다.
4. **수정 및 검증:** 승인된 구현 후 관련 성공·오류·빈 상태·로딩·뒤로가기·키보드·포커스 동작을 확인합니다. UI 변경은 두 필수 viewport에서 검증하고 전후 화면을 기록합니다.
5. **필요한 절차만 스크립트화:** 아래 기준에 맞으면 기존 테스트 구조에 회귀 검증을 추가합니다. 새 의존성이나 실행 명령 도입은 계획에 명시하고, 실제 저장소의 `package.json`을 기준으로 실행합니다.
6. **결과 보고:** 실행 명령, 실제 결과, 증거 경로와 완료·실패·보류·미검증을 구분합니다. 도구 호출 성공만으로 검증 완료를 선언하지 않습니다.

## 스크립트로 남길 기준

- 수정한 결함의 재발 가능성이 있거나 이후 작업에서 같은 절차를 반복해야 합니다.
- 입력, 기대 결과, 성공/실패 판정이 안정적으로 정의되어야 합니다. 일회성 탐색을 모두 테스트로 바꾸지 않습니다.
- 기존 테스트 계층에서 검증할 수 있는 로직은 그 계층을 사용하고, 실제 브라우저가 필요한 상호작용은 브라우저 검증으로 남깁니다.
- 접근 가능한 이름·역할 등 안정적인 대상을 사용하고, 고정 대기 시간보다 관찰 가능한 화면·응답 상태를 기다립니다.
- 입력 필드의 표시값, 실제 저장 결과와 새로고침 후 결과를 필요한 범위에서 구분해 확인합니다. 실패·재시도·복구와 관련 없는 단순 클릭 성공만 검증하지 않습니다.
- 데이터 생성·수정은 승인된 환경의 합성 데이터에 한정합니다. 생성 대상과 복구 방법을 명시하고, 기존 기록이나 다른 작업의 데이터를 일괄 삭제하지 않습니다.
- 로컬 경로·실제 계정·비밀번호·토큰·세션을 하드코딩하거나 인증 상태 파일을 커밋하지 않습니다. 실행에 필요한 전제조건을 함께 기록합니다.

## 검증 수준과 증거

- UI 변경의 최소 viewport는 **390×844**, **360×800**입니다. 관련 터치 영역 44×44px, safe-area, 입력 포커스와 키보드에 가려지는 영역을 확인합니다.
- 데스크톱 모바일 viewport 검증은 실제 iOS/Android 키보드·IME·설치형 PWA 검증과 다릅니다. 실기기 확인을 보류했다면 그대로 보류로 보고합니다.
- 기존 세션의 화면 표시, 새 자격 증명 로그인, owner/staff 권한 검증은 각각 구분합니다. 필요한 역할을 실제로 확인하지 않았다면 통과로 표시하지 않습니다.
- PWA·manifest·service-worker·캐시가 바뀌면 AGENTS.md §6.3 전체가 적용됩니다. 브라우저 도구를 바꾸어도 오프라인·재연결·데이터 최신성 검증은 생략하지 않습니다.
- 스크린샷·로그에는 합성·비식별 데이터만 포함합니다. 민감한 화면은 캡처 후 가리는 방식에 의존하지 말고 캡처 전에 데이터와 화면 범위를 조정합니다.
- 사용자 지정 환경, 재현에 필요한 브라우저 또는 필수 검증을 사용할 수 없으면 대체 검증의 범위와 남은 제한을 명시합니다.

## 시간과 토큰 사용 줄이기

기존 스크립트를 먼저 실행하고, 실패한 동작에 대해서만 탐색합니다. 전체 페이지나 같은 스크린샷을 반복 수집하지 않고 다음 판단에 필요한 화면 영역·오류·상태를 확인합니다. 통과한 검증을 새 변경이나 미해결 위험 없이 반복하지 않습니다.

Ego와 Chrome을 매번 모두 실행하지 않습니다. 도구 자체 문제인지 제품 문제인지 구분해야 하거나 브라우저 차이가 의심될 때 교차 확인합니다. 입력값이 사라지거나 스크롤 후 값이 달라지면 반복 클릭에 앞서 포커스·이벤트·실제 저장값을 확인합니다.

시간·토큰 절감은 브라우저 이름만으로 보장하지 않습니다. 비교할 때는 동일한 시나리오·데이터·환경에서 경과 시간, 호출 수, 재시도 수를 기록하고 토큰 수는 측정값이 있을 때만 보고합니다.

## 세션과 병렬 작업

탭이나 Space가 분리되어도 같은 서버 데이터는 공유될 수 있습니다. 테스트 데이터와 서버·출력 경로까지 구분하고, 다른 작업의 로그인 상태·탭·프로세스를 종료하거나 초기화하지 않습니다. 이 작업에서 만든 자원만 소유 범위를 확인해 정리합니다. 여러 Space 사용과 서브에이전트 위임은 별개이며 위임은 AGENTS.md의 요청 기준을 따릅니다.

## 기록 양식

작업 규모에 맞춰 아래 내용을 결과 보고나 해당 작업 문서에 남깁니다. 비밀값이나 인증된 세션의 내용을 붙여 넣지 않습니다.

```text
대상: 브랜치/커밋, 환경, 경로, 검증 역할
도구: 브라우저/자동화 경로, viewport 또는 실기기
시나리오: 전제조건 → 조작 → 기대 결과
실행: 명령 또는 재현 순서
결과: 완료 / 실패 / 보류 / 미검증
증거: 전후 화면·로그·테스트 파일 경로
대체 경로: 도구 변경 이유와 검증 한계(해당 시)
데이터: 합성 데이터 사용, 생성·수정·복구 결과
후속: 남은 위험 또는 실기기 확인
```

문서만 변경한 작업은 diff·경로·명령을 검증하며, UI 스크린샷과 실기기 검증은 N/A입니다. 애플리케이션 코드·설정·의존성 변경에는 AGENTS.md §6.1의 빌드 및 관련 테스트 규칙이 계속 적용됩니다.
