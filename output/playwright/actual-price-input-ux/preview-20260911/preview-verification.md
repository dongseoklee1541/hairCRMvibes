## 실제 Preview 검증
- Codex 인앱 브라우저의 390×844 및 360×800에서 `75000`을 한 자리씩 입력해도 금액 입력 포커스를 유지했습니다.
- `type=text`, `inputMode=numeric`, 숫자 패턴 확인. 390px에서 위/아래 방향키로 금액이 변경되지 않았습니다.
- 기존 `75000` 값은 창을 다시 열 때 전체 선택(0..5)돼 바로 교체됐습니다. Backspace로 빈값 만들기도 확인했습니다.
- 두 크기에서 한글 사유를 나눠 입력해도 사유 입력 포커스를 유지했습니다. 실제 OS의 조합형 IME 시험은 아닙니다.
- 완료 시술에서 사유 누락 시 브라우저 필수 입력 검증으로 저장을 막았습니다.
- `2147483648` 입력은 앱에서 최대 금액 오류로 차단했습니다.
- 합성 고객의 완료 시술 한 건을 `75000 → 0 → null`로 저장하고 각 단계마다 새로고침으로 유지 여부를 확인했습니다. 0원은 `실제 무료 (0원)`으로, null은 `실제 금액 미입력`으로 구분돼 표시됐습니다.
- 0원 단계의 첫 자동 대기 조건은 실제 표시 문구와 달라 시간 초과됐습니다. 후속 AX 화면에서 `실제 무료 (0원)`을 직접 확인했습니다. 저장 실패가 아닙니다.
- 최종 실제 금액을 원래의 미입력(null) 상태로 복원했습니다. 예약 기준은 계속 가격 미설정이며, 합성 예약 상태·횟수권 잔여와 사용 수치는 변경되지 않았습니다. 가격 수정 시각·수정 사유는 검증으로 갱신됐습니다.
- 모든 입력·버튼은 최소 44px. 390px 입력 높이 48px / 저장 56px / 닫기 44×52px, 360px도 동일 높이를 확인했습니다. 가로 넘침 없음.
- 360×450의 축소 높이에서 Tab으로 저장 버튼 접근: top 370, bottom 426으로 viewport 안에 표시됐습니다.
- Escape로 취소하면 창이 닫히고 원래 금액 수정 버튼으로 포커스가 복원됐습니다. 이 마지막 입력은 저장하지 않았습니다.
- 브라우저 도구에 기록된 console error 0건, warning 0건입니다. 전체 네트워크/PWA 회귀를 의미하지 않습니다.
